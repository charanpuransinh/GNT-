# GNT — टीम C (M11–M15) मास्टर वर्ज़न — कैसे बना

आपके कहे अनुसार अब हर मॉड्यूल की **सिर्फ एक ही, सबसे अच्छी कॉपी** रखी गई है। जहां भी एक ही फाइल 2-5 अलग-अलग
zip में मिली, वहां मैंने सिर्फ नाम या तारीख नहीं देखी — **हर कॉपी का असली कोड खोलकर पढ़ा**, फिर तय किया कि कौन सी
कॉपी रखनी है:

- जो फाइल में सिर्फ 5 लाइन का खाली ढांचा (skeleton — बस export/खाली फंक्शन) था, उसे हटाया
- जो फाइल में असली लॉजिक (function/service/controller की पूरी बॉडी) था, उसे रखा
- जहां दोनों में असली कोड था, वहां जिसमें ज़्यादा पूरा/बड़ा (ज़्यादा लाइनों वाला, कम TODO/placeholder वाला) काम था, वो रखा

- M15 का `sync.service.ts` — 5 अलग जगह मिला (5 लाइन का खाली ढांचा से लेकर 534 लाइन तक)। सबसे पूरा (534 लाइन, असली लॉजिक वाला — `SESSION_8_M15_SYNC`) रखा गया।
- M11 का `payment.service.ts` — STRUCTURE zip में सिर्फ 5 लाइन का खाली ढांचा था, असली 222 लाइन वाला वर्ज़न `SESSION_3_M11_PAYMENT_FULL` से रखा गया।
- M14 का `import.service.ts` — 223 लाइन वाला (`SESSION_6_M14_IMPORT_EXPORT`) 121 और 5 लाइन वाले वर्ज़नों से बेहतर पाया गया, वही रखा गया।

**ध्यान दें:** `GNT_TEAM_C_M11-M15_STRUCTURE.zip` वाली फाइलें ज़्यादातर सिर्फ 5-लाइन का खाका (structure/skeleton) निकलीं
— असली काम नहीं। इसलिए जहां भी असली इम्प्लीमेंटेशन कहीं और मिला, वहां structure वाली कॉपी हटा दी गई।

## Master Package में क्या है

```
modules/
  m11-payment/      ← 96 फाइलें (सिर्फ सबसे अच्छा वर्ज़न)
  m12-hr/           ← 58 फाइलें
  m13-automation/   ← 110 फाइलें
  m14-import-export/← 149 फाइलें
  m15-sync/         ← 61 फाइलें
_shared/            ← wiring maps, seed data, cross-module flows, API contracts
```

आप पुरानी सारी 16 zip फाइलें डिलीट कर सकते हैं — यही एक Master zip उनकी जगह ले लेगा।

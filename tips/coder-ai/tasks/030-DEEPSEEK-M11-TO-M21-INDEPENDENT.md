## ✅ "पूरा हुआ" का मतलब क्या है (मालिक की सख़्त परिभाषा — 2026-09-04)

पुराना ढीला मतलब **ख़त्म**। अब पाँचों बातें एक साथ सच होनी चाहिए:

1. **live database पर चलकर** जाँचा हो — mock पर नहीं (`pg_isready` से पक्का करो DB चालू है)
2. सुविधा **सिरे से सिरे तक सच में चले** — कोई `return false` नहीं, कोई बिना चली migration नहीं
3. **एक भी खुली शर्त नहीं** — अगर लिखना पड़े "पर यह बाक़ी है", तो वो module पूरा नहीं है
4. tests **`TEST_DB=1`** के साथ पास हों — इसके बिना tests चुपचाप skip होते हैं
5. तुमने **ख़ुद चलाकर** देखा हो

**चलाने का सही तरीक़ा:**
```bash
cd GNT_GITHUB_REPOSITORY/backend && TEST_DB=1 npx vitest run
```
रिपोर्ट में **skip की गिनती भी** लिखो। `skipped` दिखे तो "सब पास" लिखना झूठ है।

   पूरे कोड में अभी **193 जगह** ये मौजूद हैं। अपने modules में **नए मत जोड़ो**, और जो

2. **`TODO` छोड़कर "पूरा" लिखना।** TODO बचा है = module पूरा नहीं है।
3. **migration फ़ाइल बनाकर छोड़ देना।** बनाई है तो **चलाओ भी**। `<app_user>` जैसा
   placeholder बचा रह गया तो वो सुरक्षा लागू ही नहीं हुई।
4. **हरा शीर्षक, नीचे शर्तें।** यह प्रोजेक्ट की सबसे महँगी ग़लती रही है (Claude ने की थी,
